I

Abstract

Not every instruction needs a language model.

Robots need to connect what people ask for with places they can drive to. SAS answers what its rules can accept, escalates the rest to a VLM, and turns stable model answers into memory a second robot can reuse.

This paper presents the Semantic Autonomy Stack (SAS), a six-layer integration framework, and develops its semantic-reasoning, mission-interface and operational-memory layers over a previously validated ROS 2/Nav2 foundation. A deterministic-first cascade combines the route graph, semantic objects, robot state and stored instruction–destination associations, escalating unresolved or guarded cases to a pretrained Vision-Language Model. SAS keeps destination selection, action validation, navigation execution and post-arrival confirmation separate.

Recurrent model-mediated associations can pass a frequency-and-consistency gate and be compiled for deterministic M3 reuse; the paper stresses that this gate measures sampled-output stability, not semantic truth. The frozen v4.8-review implementation was evaluated on two physical robot configurations in one indoor environment. Of 216 decision cycles outside the start gate, 112 resolved deterministically at sub-millisecond resolver-compute latency. A sealed 28-instruction challenge yielded 17 acceptable outcomes; its five fast-path decisions included one incorrect selection. One promoted association was reused on the second platform through deliberate shared-digest installation, and a controlled 594-observation offline comparison showed greater agreement with stored associations and lower latency from M3 reuse on five familiar cases. Large latency savings were concentrated in paths that avoid VLM inference.

III

Method in motion

From a sentence to a goal node.

Mission console. An instruction enters at L4 and is resolved at L3: deterministically when a rule or stored association applies, through the VLM when it does not. Only a validated, graph-valid node is handed to Nav2 at L1; arrival and confirmation are logged as separate events.

The paper describes the system as a distributed robot–workstation deployment, not fully onboard GPU-free semantic inference. Metric navigation and the localisation loop always stay on the robot.

B.The seven-step deterministic resolver

Before any step runs, a negation and exclusion guard reads the raw normalised wording; if it fires, the cascade is skipped and the instruction goes to a negation-aware L3b path with a forbidden-node set, so neither memory nor an explicit node reference can override “not there”. Otherwise the first step that produces an admissible candidate wins:

  1. Step 0 · M3 associationReuse a promoted instruction–node association if Jaccard ≥ 0.75 and it leads the runner-up destination by ≥ 0.10; otherwise fall through, not escalate.
  2. Step 1 · Explicit node IDA numeric graph-node command, exempt from the location check.
  3. Step 2 · Node nameA unique normalised node-name match.
  4. Step 3 · Object IDA unique semantic-object identifier.
  5. Step 4 · AttributeA unique best word-bounded attribute match; no affordance is inferred.
  6. Step 5 · Single classOne mentioned class with one candidate object, surveyed objects first.
  7. Step 6 · Class + proximityOne class, several objects, a proximity cue: nearest to the current pose.

A candidate that contradicts an explicit room or lab identifier in the instruction is escalated as a location conflict. If nothing is admissible, the decision goes to L3b. The resolver is deterministic given the same instruction, graph, objects, pose and installed memory; which step resolves a request depends on the workload.

C.A constrained VLM and a contract around it

L3b does not emit robot commands. It selects a destination through a fixed multimodal interface: the installed memory prefix, robot state, the graph with node identifiers and coordinates, semantic objects grouped by region, designated seating and resting information, and the task with explicit response rules. The model must answer with an integer node identifier and a reason; -1 means clarification.

The parsed proposal then passes the executive contract ⟨A, O, V, L⟩ adopted from ROSClaw: Affordances (graph-grounded targets and admissible actions), Observations (normalised state and context), Validation against graph and safety constraints, and Logging of the path, timing and outcome. Invalid nodes, forbidden destinations and -1 never produce a navigation command.

Post-arrival confirmation is its own decision. For landmark and contextual destinations the system checks an arrival image against the expected context; for others it uses a pose-based check, which supports arrival at a location, not visual detection of an object. A completed navigation followed by a negative confirmation is not rewritten as a navigation failure.

Only pretrained models are used: no task-specific fine-tuning and no separately trained routing classifier.

Memory extraction is offline over a selected audit subset. Instructions are grouped by a canonical key built with the same text processing as the resolver. A candidate is promoted only when frequency ≥ 3, rounded consistency ≥ 0.80, and at least one accepted L3b resolution exist, so instructions the cascade already handles do not become rules.

Compilation and installation are separate, deliberate steps: a new association does not become active just because extraction ran. Cross-platform use is shared-memory reuse through a managed digest, not autonomous peer-to-peer learning, and a promoted M3 item is a learned association, not a validated operator preference.

E.A frozen build and a confirmatory campaign

All confirmatory evidence comes from Session E, run against one frozen build (v4.8-review, commit f973aa0c, clean working tree at every one of 214 startups) with fixed model, graph, ontology and parameters. Its blocks test different capabilities with different experimental units, so the paper reports no pooled N. Earlier development Sessions A–C are kept as history, not as estimates of final-system performance.

V

Results

What worked, where it failed, and why.

A.Deterministic reasoning

Outside the start gate, 112 of 216 decision cycles were resolved by the cascade without a model call and 104 entered the L3b path. The learned-association step resolved 39 of the 112. The paper is explicit that this proportion describes the instruction mix the campaign was built to probe, from every cycle in the repeatability block to none in the promotion and concurrency blocks, not a resolver-wide rate.

Between naturally selected paths, the ratio of median decision latency (accepted L3b vs deterministic) was 45,443×, 95% cluster-bootstrap interval 30,428–70,512×. These arms contain different instructions, so this is not a causal VLM-only baseline. In the repeatability block all 11 intents (56 cycles) resolved deterministically with an invariant method, step and destination: repeatability, not correctness.

B.Hard cases: unseen wording and negation

The sealed challenge had 28 instructions with acceptable-destination sets fixed before execution. 17/28 were acceptable: 6/6, 2/6, 4/6 and 2/6 across difficulty levels P1–P4 and 3/4 in the extra cells. Six went to a wrong destination, two executed where the key required clarification, three ended in parsing failures, and no clarification request was ever issued.

Five cells took the fast path; one of them, G-3 “Where is the H sign?”, resolved at Step 5 to a node carrying a YOLO stop-sign object through a partial class match on “sign”. An independent evaluator who had not built or run the test agreed with the sealed verdict in 26/28 cells; rescoring under his judgments gives 16/28.

In a deployed-navigator branch test, all 27 forbidden integer proposals were rejected without dispatch. The same test exposed a parser weakness: a boolean true as node_id reached dispatch as node 1 in 14/14 synthetic cases. None of the 91 recorded Session E proposals was non-integer.

C.Memory: promotion, reuse and removal

Three controlled candidates were each observed four times with an accepted L3b answer, so consistency decided: wet_gloves (1.00) promoted, quiet_corner (0.75) and deliveries (0.50) were rejected. A post-hoc sweep showed every threshold from 0.76 to 1.00 gives the same outcome.

E4b ran the whole chain: a baseline cycle on Xplorer-B needed L3b; four induction cycles on Xplorer-C chose the same node; the association was promoted, compiled and deliberately installed; four cycles on Xplorer-B then resolved at Step 0 with Jaccard 1.00 and no model call. Those are four verifications of one association.

E6 removed the compiled memory layer for four instruction-by-platform pairs: every unit escalated to L3b and every one chose a different destination; the paired latency ratio had a median of 75,500× (72,039–88,269×). M3 and the M1/M2 prompt prefix were removed together, so the change cannot be pinned on M3 alone.

D.A controlled comparison: complete, M3-off, VLM-only

Three arms resolved the same 38 standardized instruction-context items, three seeds each: A the complete system, B the cascade with M3 disabled, and C direct VLM resolution, all with the same context, safeguards and validation. Across both conditions, 594 observations.

On the five familiar items, A agreed with the stored associations on 5/5 items (15/15 observations) versus 4/5 for B and C, and made no VLM calls. On unseen formulations M3 added nothing. B and C made identical decisions in all 114 paired observations while B used 99 instead of 114 VLM calls: the cascade reduced invocation without observed quality superiority.

E.Swapping the VLM

68 archived, image-complete Session E records were replayed through the unchanged prompt and parser with the control model and two substitutes, at three seed bases: 612 outputs in the primary analysis. All three models could drive the interface, but they behaved differently: parser compliance 88.7%, 100% and 97.5%; same-node seed unanimity 40/68, 66/68 and 50/68; median latency 7.20 s, 6.77 s and 14.63 s.

Agreement with the archived node is reference agreement against one recorded stochastic outcome, not accuracy, and the cohort only includes cases the original system resolved. The paper's conclusion is narrow on purpose: interface portability, not semantic model invariance. On the 13 negation records, none of 117 outputs proposed a forbidden node.

VI

Limitations and next steps

The paper draws its own claim ceiling.

Limitations, as the paper states them

  • Narrow external validity. Two robot configurations, one indoor environment, one route graph; no second building, no varied POI density, no symmetric layouts or systematic occlusion.
  • Stable is not correct. The M3 gate measures recurrence of model outputs; there is no operator-confirmation field, so a stable but wrong association can still be promoted and then bypass the VLM.
  • Memory layers not isolated. E6 removes M3 with M1/M2; M4 and M5 are not independently evaluated.
  • Imperfect routing boundary. E7 includes wrong executable decisions, three parsing failures and zero clarification requests; partial class matching caused the G-3 error.
  • Lexical matching. At the operational threshold the matcher accepted 10/16 valid paraphrases but also 9/15 high-overlap items with a different meaning.
  • Parser typing. The deployed parser does not type-check node_id; the frozen code was left unchanged and the weakness reported.
  • Reproducibility differs by evidence. Session E is frozen and public; the navigator, executive contract and memory extractor are protected modules, available to reviewers on request.

Development routes named in the paper

  • Typed response validation in the L3b parser.
  • Stronger deterministic discrimination, to reduce partial-match and lexical-overlap errors.
  • Independent confirmation before promotion: explicit user feedback or another semantic-validity signal for stronger preference claims.
  • Broader environments and instruction sets, and separate evaluation of M1, M2, M4 and M5.
  • Fleet-scale exchange beyond two robots, studied explicitly rather than assumed.
  • Localisation checks: frame alignment and camera-robot extrinsics, with broader independent reference coverage.
