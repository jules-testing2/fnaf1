Semantic Autonomy Stack · SAS

Intent in. Motion out.

SAS is our six-layer integration framework for indoor robots. It turns an operator's words into a graph-grounded destination, hands that goal to Nav2, checks what the robot finds on arrival, and keeps a scoped memory of what worked. Rules first. A vision-language model only when the rules abstain.

Six layers · one boundary each

Read the stack from the wheels up.

Each layer prescribes a capability and an interface, not one implementation. L0 to L2 are the navigation and perception foundation validated in our Sensors 2026 study. L3 to L5 are the reasoning, mission and memory layers developed and evaluated in the published SAS paper.

L0

Inherited foundation

Mobile platform

Locomotion, onboard sensing, power, low-level control and the compute that rides on the robot. SAS prescribes no particular body: L0 supplies the platform-specific capabilities that every higher layer depends on.

I/Ocmd_vel → sensor streams

L5L4L3L2L1
L0 contract · cmd_vel in · sensor streams out

One stack, every body is a design goal: the layers above L0 do not change when the body does. The published physical validation covers two differential-drive configurations, Xplorer-B and Xplorer-C, in one indoor environment.

L1

Inherited foundation

Navigation execution

Localization, route planning, path following and local obstacle avoidance, all in metric space. L1 receives an admissible goal or route from L3 and executes it with ROS 2 and Nav2, without needing to know what the destination means.

I/Ogoal / route / action → cmd_vel + action result

  • AMCL + EKF
  • Nav2 Route Server
  • MPPI controller
  • penalty-weighted replanning

Semantic penalties on graph edges re-score the route; when an edge on the current route changes by more than a threshold, the route is recomputed. Sensors 2026: 115 navigation legs on three robots, 97% overall success, 42 replanning events.

L2

Inherited foundation

Perception & semantic map

Camera frames and LiDAR scans become localized semantic context: what is where, in the map frame. L2 feeds L3 with objects to reason about, and it can push semantics straight into L1 as edge penalties.

I/OLaserScan + Image + AMCL pose → semantic context

  1. DetectYOLO26n on the robot's Raspberry Pi 5, NCNN backend, 5.5 ± 0.7 FPS (167 ± 21 ms).
  2. FuseAngular Sector Fusion projects each box onto LiDAR rays and takes the 25th-percentile range. No learned parameters.
  3. RememberA persistent GeoJSON map classifies objects by mobility and turns them into edge penalties.

L3

Developed in the SAS paper

Semantic reasoning

The bridge from words to a destination. L3a, a seven-step deterministic resolver, tries the graph, the semantic objects, the robot's pose and learned associations first. If it abstains, or a safeguard fires, L3b asks a pretrained VLM through a fixed prompt and parser, and the answer is validated before anything moves.

I/Oinstruction + context + digest → goal / route / action + audit entry

  1. GuardNegation or exclusion? Skip to L3b.
  2. S0Reuse a learned association · J1 ≥ 0.75, margin ≥ 0.10
  3. S1Explicit node ID
  4. S2Node name match
  5. S3Object identifier match
  6. S4Attribute scoring
  7. S5Single object class
  8. S6Class + proximity

Location referents that contradict the instruction escalate instead of executing. VLM replies outside the forbidden set and inside the graph pass the executive contract ⟨A, O, V, L⟩: affordances, observation, validation, logging.

L4

Developed in the SAS paper

Mission interface

The boundary between people or fleet systems and the reasoning layer. L4 accepts natural-language and structured operator or fleet commands and forwards them through one stable interface, so the same higher-layer logic serves either robot. It is designed to accommodate standard fleet interfaces such as VDA 5050.

I/Ooperator NL / fleet cmd → instruction to L3

L5

Developed in the SAS paper

Operational memory

Audit history becomes scoped memory and a compact runtime digest. M1 to M3 are shared across platforms, M4 and M5 stay platform-aware. Only M3 can change the resolution path: a promoted instruction–node association is matched at Step 0 and skips the VLM.

I/Oaudit entries (from L3) → compiled digest

M3 promotion gate f ≥ 3c ≥ 0.80≥ 1 accepted L3b resolution

The gate measures how stable a sampled answer is, not whether it is right: a stable but wrong association could pass. In a nine-arm model and seed replay, wet_gloves promoted in 9/9 arms while the archived quiet_corner rejection flipped in 8/9.

Design principles

One stack, every body.

Body-agnostic

Layers are defined by responsibilities and interfaces. Change the body at L0 and the layers above keep their contracts; behaviour still has to be validated on each new platform.

Deterministic first

Rules over the graph, objects and stored associations run before any model. The VLM is the escalation path, not the default.

Abstain, don't guess

Negation outranks every step, location conflicts escalate, near-ties abstain, and an invalid or forbidden VLM answer is blocked and logged without moving the robot.

Grounded, not just labelled

Every target is a node in the route graph tied to surveyed objects. Choosing a destination, arriving and confirming what is there are recorded as three separate events.

Auditable by construction

Each decision leaves an audit record with its resolution path, validation state and outcome. Memory is rebuilt from those records, never from hidden state.

Edge hardware

Robots carry Raspberry Pi 5 boards and no GPU. Only the selective VLM path needs a GPU, on a shared workstation.

Positioning

The ingredients exist. The integration is the point.

Selective reasoning, embodied memory and LLM–ROS interfaces each have strong precedents. SAS combines them under one explicit decision boundary. Summarised from Table 1 of the SAS paper: published capabilities, not benchmark results, and the other systems were not rerun.
